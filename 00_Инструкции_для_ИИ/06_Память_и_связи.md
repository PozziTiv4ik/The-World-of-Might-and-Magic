## Документы и ID

В шапке документа хранится неизменяемый id. CHAR — персонаж, LOC — место, ASSET — актив, SCENE — сцена, SRC — исходное сообщение, LORE — лор. Имя файла можно менять, сохранив ID и обновив явные ссылки. Старые числовые ID и новые UUID одинаково допустимы.

Сцена поддерживает массивы source_ids, participant_ids, front_ids в однострочном JSON внутри шапки. Старое front_id сохраняется для совместимости. participant_ids означает связь с разделом участников: присутствие в комнате, сон, донесение и отсутствующий адресат различаются в тексте.

Граф извлекает прямые ссылки; обратные ссылки входящих связывают сцену с источником только при явно общей записи. Сходство заголовков не является доказательством. provenance unresolved означает, что прямое основание ещё не связано; такие связи нельзя выдумывать.

У решения есть неизменяемый uid, а id остаётся привычным DEC или DEC-PENDING. При закрытии сохраняются resolved_from, original_question и transitions. Исторические связи старых решений без доказанного соответствия не реконструируются по совпадению чисел.

## Знания

Каждая запись хранит id, text, truth, evidence_ids, subject_ids, known_to, visibility, story_time и recorded_on.

truth: confirmed, reported, rumor, dream, legend, inference, unknown.
visibility: public, restricted, gm.
known_to содержит ID персонажей, которым сведения действительно известны.

Например, разговор о легенде достоверно состоялся, но содержание легенды не становится confirmed. Сон Михаэля остаётся dream. При неустановленном круге знающих список пустой; персонажный контекст исключает запись.

Новый факт добавляй с основанием. Изменение текущего состояния не стирает прежнее событие. Относительные даты не превращай в точные без канона. После решения обновляй связанные факты и положение ветки, а не только статус DEC.

## Память NPC и сцены

Собрать_память берёт черты, цели и существующие связи из карточек и присоединяет известные факты. Отсутствующая манера речи отмечается not_established. При появлении канонической реплики можно заполнить раздел Манера речи со ссылкой на сцену.

Сцена должна различать интересы участников, предмет конфликта, подтверждённые знания и последствия. Историческое упоминание не доказывает сегодняшнюю должность или присутствие.

## Выбор контекста

Получить_контекст поддерживает Branch, Query, Entity, Audience и MaxWords. Результат включает основания и причину выбора материалов. Json возвращает также список опущенных блоков.

Стандартный порядок: явно текущие узлы, соответствие ветке/запросу, приоритет, стабильный ID. Мировые вопросы участвуют в том же отборе. attention в вопросах — техническая очередь внимания; исходный статус и ID не теряются.

Неизвестность, ждёт ли вопрос конкретного события, сохраняется в waiting_for. Не закрывай вопрос из-за возраста. Лимит объёма не означает, что остальные сведения не существуют.

## Подготовка и применение

Начать_ход создаёт копию и исходные хеши в локальной .wmma. После работы Подготовить_ход выполняет полную сборку и проверку копии и сохраняет список файлов с хешами до/после. Применить_ход проверяет неизменность копии и исходных зависимостей, затем пишет изменения с журналом и резервными файлами.

При сбое Восстановить_ход с Mode resume продолжает применение. Mode restore восстанавливает только файлы этого хода и отказывается затирать посторонние изменения. Команды повторяемы. Удаление временных копий не является условием успешного хода.

Рабочая копия — технический механизм, не отдельная сюжетная ветка. Источники внутри неё сохраняют обычный жизненный цикл.

## Проверки

Проверить_проект включает Проверить_контекст: схемы JSON, уникальность ID, свежесть графа и пакетов, ссылки знаний, общий контекст веток, выбранные вопросы, циклы времени и сохранность исторических документов. Проверить_инструменты и Проверить_систему_v2 выполняют сценарии на копиях.

Проверка не доказывает истинность произвольного литературного утверждения. Противоречия проверяются по двум фрагментам и основаниям; сомнительное исправление не вносится в канон автоматически.
