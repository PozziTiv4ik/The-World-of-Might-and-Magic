Runtime — PowerShell 7. Все команды ниже — `.ps1` в этой папке. Пользователь пишет обычные сообщения; агент ведёт файлы по [AGENTS.md](../AGENTS.md). Контракт данных и знаний — [Память и связи](../00_Инструкции_для_ИИ/06_Память_и_связи.md).

## Рабочий маршрут

`Начать_ход -Id TURN-... -Title ...` → изменения в возвращённой копии → `Подготовить_ход -Id TURN-...` → `Применить_ход -Id TURN-...`. При прерывании — `Восстановить_ход` с тем же ID: `-Mode resume` продолжает, `-Mode restore` возвращает собственные изменения с проверкой посторонних правок, `-Mode rebase` переносит неприменённый ход (editing, prepared) на текущие файлы, если посторонние правки затронули другие файлы; после него снова нужен `Подготовить_ход`. Во время сюжетного хода Regnum закрыт: его автосохранение — посторонняя правка мира. Порядок сюжетных действий: [Ведение игры](../00_Инструкции_для_ИИ/01_Ведение_игры.md).

`Список_ходов` показывает журналы `.voidlight/turns`: статус, начало, последнюю запись и размер копии. `-Clean` удаляет копии завершённых ходов (committed, restored), `-Discard -Id` — копию неприменённого хода (copying, editing, prepared); наполовину применённый или восстановленный ход не удаляется. `Проверить_проект` даёт ошибку на журнал applying или restoring и предупреждение на copying, editing, prepared.

После технических правок выполняй `Завершить_ход`. Он собирает граф, индексы, представления реестров, панель, контекст, память и аудит, затем проверяет проект. Каждый генератор запускается один раз; дата неизменного представления не обновляется.

## Чтение

| Команда | Параметры |
| --- | --- |
| Получить_контекст | `-Branch Михаэль`, `-Query капитал`, `-Entity ASSET-0056`; `-MaxWords` по умолчанию 2000; `-Json` включает причины отбора и опущенные блоки |
| Получить_контекст для персонажа | `-Audience character` и ветка или `-Entity CHAR-…` (NPC без ветки). Минимальный фильтр: факты с явным кругом знающих, «Что известно персонажу» из сцен его линии с его участием, манера речи и список прочих сцен с участием; ID реестров скрыты |
| Получить_связи для ведущего | `-Entity ID`, `-Depth` от 1 до 3, `-MaxNodes` от 1 до 200, `-Json`; по умолчанию один переход и 20 соседей; `-IncludeReferences` добавляет упоминания, `-IncludeHistory` — исторические связи |
| Сверить_мир_Regnum | Только чтение, без редактора: поля `entity` мира в 12_Карты ведут на существующие необъединённые карточки с подходящим префиксом, «Мертв» героя совпадает со статусом карточки; `-World`, `-Json` |

## Запись и сборка

| Данные | Запись | Представления |
| --- | --- | --- |
| Сообщения | Принять_сообщение, Обработать_входящее | Собрать_индекс_источников |
| Сцены | Сцена_из_входящего, Новая_сцена: `-SourceIds`, `-ParticipantIds`, `-FrontIds` | Собрать_индекс_сцен, Собрать_связи |
| Персонажи и места | Новый_персонаж, Новая_локация: `-Aliases`, `-DistinctFrom` | Собрать_индекс_персонажей, Собрать_индекс_локаций |
| Дубли | Объединить_сущности: `-From`, `-Into`, `-Reason` | Собрать_связи |
| Портреты и активы | Новый_портрет; правила в профильных инструкциях | Собрать_индекс_активов (общий и по владельцам) |
| Решения | Новое_решение (`-SceneIds` обязателен), Закрыть_решение | Собрать_решения |
| Вопросы | Новый_вопрос: `-Attention`, `-WaitingFor`, `-OpenedInChapter`; Закрыть_вопрос | Собрать_вопросы |
| Фронты | Новый_фронт, Обновить_фронт | Собрать_фронты |
| Знания | Новое_знание: Text, Truth, EvidenceIds, KnownTo, KnowledgeEvidence `CHAR-…\|ID,ID\|основание` на каждого знающего, `-Supersedes`; Заменить_факт | Собрать_память |
| Положение ветки | Обновить_контекст_ветки: Branch, SceneIds, FactIds, FocusIds, Situation; `-Global` — общая точка; `-Create -CharacterId` — новая ветка | Собрать_контекст, Собрать_панель_хода |
| Относительное время | Новая_связь_времени: From, To, Relation, EvidenceIds | Проверка порядка событий |
| Главы и закрытый канон | Закрыть_главу: Chapter, NextTitle, NextDateInStory; Обновить_защиту_канона: Path, Reason, `-Add` | Собрать_индекс_сцен |
| Срезы и покрытие | Исходные реестры и карточки | Собрать_срезы_реестров, Собрать_аудит_данных |

Приём по умолчанию создаёт отдельный источник; `-Mode inbox` сохраняет только входящее. `RequestId` отличает сообщения и защищает от повторов.

Новый персонаж или место получает числовой ID сразу. Совпадение названия или псевдонима с существующей карточкой (полное или вложенное: «Закхерон» — «Закхерон Багровый») — отказ с перечнем карточек: используй существующую или подтверди различие `-DistinctFrom ID`. `-Force` у этих команд нет: существующая карточка правится вручную с сохранением ID. `Объединить_сущности` переносит псевдонимы и поля-ссылки метаданных и реестров на основной ID, хранит прежний текст как историю основной карточки, а дубль оставляет перенаправлением (`merged_into`, `status: merged`); текст сцен не меняется, ссылки мира Regnum команда только перечисляет.

`-SkipCheck` откладывает проверку; созданные документы сразу регистрируются в `Сущности.json`, поэтому следующие команды пакета видят их ID. Полный граф пересобирает `Завершить_ход` или `Подготовить_ход`. У сборщиков решений и вопросов `-Only` отключает также зависимые сборки; этот режим использует `Завершить_ход`. Команды читают авторитетные JSON и не правят генерируемые представления. Старый `-ImportFromMarkdown` удалён: потерянный реестр восстанавливают из проверенной копии, не из его представления.

## Поддержка

`Проверить_проект` объединяет проверки структуры, ссылок, реестров, контекста и сохранности истории, а также журналов ходов, словаря статусов персонажей, дублей названий, закрытых сцен и необязательную сверку мира Regnum (её находки — предупреждения). Профильные команды: `Проверить_архив`, `Проверить_портреты`, `Проверить_реестры`, `Проверить_контекст`. Сценарные наборы `Проверить_инструменты`, `Проверить_сценарии_контекста`, `Проверить_аудит`, `Проверить_связи` работают на фикстурах. `Проверить_инструменты` удаляет свою временную копию при любом исходе, остальные — только после успешного прогона; `-KeepFixture` оставляет копию (прежнее `-KeepTemp` у `Проверить_инструменты` тоже принимается). В GitHub Actions Project Check запускает `Проверить_проект` на пуш в main и pull request (правки только кода, ресурсов и сборок Regnum его не запускают), а Tools Check запускает сценарные наборы только при изменении скриптов, схем реестров или hooks; вручную — кнопкой Run workflow. Hooks подключает `Установить_git_hooks`.

`_lib.ps1` загружает восемь библиотек: Core — общие операции, ID, имена и защита канона; Graph — извлечение привязок и регистрация документов пакета; ReadModel — индексы и снимок реестров; Context — отбор, память и пакеты; Connections — навигация и порядок событий; Transactions — безопасная запись, перенос и список ходов; Views — шапки, таблицы и индексы активов; Checks — набор проблем, общие проверки канона и сверка с Regnum. В самом `_lib.ps1` `Invoke-VoidlightTool` вызывает соседнюю команду, а `Complete-VoidlightMutation` завершает команду записи: регистрация документов (`-Documents`) или полный граф (`-FullGraph`) при `-SkipCheck`, пересборка представлений, затем `Завершить_ход`, если проверку не отложили. Сценарные наборы подключают ещё `lib/Testing.ps1`. Снимок передают через `-Data` только внутри одной операции чтения и обновляют после записи. Команды берут общую блокировку проекта (вложенный вызов в том же процессе её переиспользует); без неё работают только наборы, меняющие лишь свои фикстуры: `Проверить_сценарии_контекста`, `Проверить_аудит`, `Проверить_связи`.

Мир и карта обслуживаются отдельно: [редактор Regnum](Regnum/README.md), [правила редактора](../00_Инструкции_для_ИИ/07_Редактор_карт.md).
