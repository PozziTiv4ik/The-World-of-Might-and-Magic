Справочник по файлам мира Regnum для людей и агентов, которые читают и правят JSON вручную. Код — `src/core/io*`, модель данных — `src/core/world.h`, перечисления и пределы — `src/core/schema.cpp`. Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md), формулы — [RULES.md](RULES.md).

## 1. Коротко для правки вручную

1. Мир — папка с `world.json` и `data/*.json` (или архив `.regnum` с той же раскладкой). Каждая таблица — отдельный файл.
2. Кодировка UTF-8 (BOM допускается), переводы строк LF. Порядок ключей и отступы при чтении не важны: файл получит канонический вид (раздел 3.1), когда редактор в следующий раз запишет его таблицу.
3. Ссылки — строки с префиксом вида: `"p12"` — провинция 12, `"f3"` — фракция 3 (таблица в разделе 3.3). Пустая ссылка — `null`.
4. Новую запись добавляйте с ID = `meta.seq.<вид> + 1` и увеличьте этот счётчик в `world.json`. Запись без `id` тоже читается: ей назначается новый ID (с предупреждением).
5. После правки запустите проверку: `regnum-cli validate <папка мира>` (раздел 13). Код возврата 0 — мир в порядке.
6. Ошибочные значения не роняют редактор: при чтении они исправляются (раздел 11), а каждое исправление попадает в список предупреждений с указанием файла и места (`data/provinces.json: p12.owner: нет фракции f9 — владелец удалён`). Исправленный мир записывается при следующем сохранении.
7. Не правьте файлы, пока мир открыт в редакторе и в нём есть несохранённые изменения: редактор заметит внешнее изменение (раздел 9) и предложит перечитать мир, но несохранённая работа в редакторе и ваша правка в одном файле не объединяются.

    characters.json          персонажи
    relations.json           отношения между фракциями
    modifiers.json           модификаторы (наборы эффектов)
    buildings.json           постройки (общее дерево и уникальные постройки фракций)
    techs.json               технологии (деревья фракций)

    routes.json              торговые маршруты

    index.json               список снимков ходов и ветвь сохранённого мира

Лишние файлы JSON в `data/` не читаются — о них тоже выводится предупреждение (частая ошибка — имя `province.json` вместо `provinces.json`).

## 3. Общие правила

### 3.1 Запись файлов

Редактор пишет файлы так, чтобы диффы в Git были минимальными:

- JSON с отступом 2 пробела; ключи объектов отсортированы по байтам UTF-8 на всех уровнях;
- записи таблиц — по возрастанию ID; элементы списков внутри записи — в порядке, заданном пользователем;
- массив из одних скаляров (`["m1", "m2"]`, `[210.5, 300.25]`) — в одну строку;
- `data/geo.json` и `data/relations.json` — одна запись на строку (компактно, ключи отсортированы);
- перевод строки LF, в конце файла — перевод строки;
- каждое поле записывается всегда, даже со значением по умолчанию (кроме эффектов модификатора: только заданные);
- запись атомарная: временный файл и замена; `world.json` пишется последним.

Сохраняются только файлы изменённых таблиц и отсутствующие на диске файлы. Файл, содержимое которого совпадает с новым, не перезаписывается.

### 3.2 Числа

- Числа JSON — double. Целые записываются без дробной части, остальные — кратчайшим точным десятичным представлением (`0.3`, `15000.5`).
- Координаты карты (узлы, точки дуг, войска, маршруты) и положения на схемах деревьев (`pos` построек и технологий) округляются при записи до 0,01.
- Целочисленные поля (численности, население, ходы, уровни) — целые; дробное значение округляется с предупреждением. Число, записанное строкой (`"12"`, `"1 200,5"`), принимается с предупреждением.
- `NaN` и бесконечности в JSON не записываются; нечисловое значение заменяется значением по умолчанию.
- Система координат карты — пиксели исходного изображения 8000 × 4500, ось Y направлена вниз. Точки вне карты переносятся на край.

### 3.3 Идентификаторы и ссылки

ID — целое > 0, у каждого вида своя последовательность (`meta.seq`). Удалённые ID не используются повторно. В файлах ID и ссылки записываются строкой с префиксом вида:

| Вид | Префикс | Пример | Счётчик в `meta.seq` |
| --- | --- | --- | --- |
| провинция | `p` | `p12` | `province` |
| фракция (государство или гильдия) | `f` | `f3` | `faction` |
| персонаж | `c` | `c7` | `character` |
| модификатор | `m` | `m2` | `modifier` |
| постройка | `b` | `b5` | `building` |
| технология | `t` | `t9` | `tech` |
| войско или флот | `a` | `a4` | `army` |
| торговый маршрут | `r` | `r1` | `route` |
| сделка | `d` | `d2` | `deal` |
| запись хроники | `l` | `l100` | `log` |
| строка армии или флота фракции | `u` | `u3` | `row` |
| место в совете фракции | `k` | `k1` | `council` |
| ресурс | `rs` | `rs2` | `resource` |
| раса | `rc` | `rc1` | `race` |
| культура | `cu` | `cu1` | `culture` |
| религия | `rl` | `rl2` | `religion` |
| форма правления | `gv` | `gv1` | `government` |
| должность | `po` | `po1` | `position` |
| эссенция элемента | `es` | `es18` | `essence` |
| реликвия | `re` | `re1` | `relic` |
| особый отряд | `su` | `su1` | `special` |
| группа ресурсов | `rg` | `rg4` | `resGroup` |
| класс героя | `hc` | `hc3` | `heroClass` |
| талант (дерево класса) | `tl` | `tl12` | `talent` |
| группа реликвий | `rlg` | `rlg1` | `relicGroup` |
| археологическое место | `as` | `as7` | `archSite` |
| сундук сокровищ | `ch` | `ch16` | `chest` |
| археологическая группа государства | `ag` | `ag2` | `archGroup` |
| узел геометрии | — | `17` | `node` |
| дуга геометрии | — | `40` | `edge` |
| знак карты (гора, замок, башня) | — | `5321` | `symbol` |
| фигура карты (вода, островок, стена, река) | — | `156` | `shape` |

- Чтение принимает и число (`12`), и строку из цифр (`"12"`). Префикс другого вида — ошибка ссылки (`"p3"` там, где ожидается фракция, удаляется с предупреждением).
- Пустая ссылка — `null` (при чтении также `0` и `""`).
- Строки армии и флота (`u`) — общая последовательность всего мира: ID строки уникален среди всех фракций. Места в совете (`k`), таланты (`tl`) и археологические группы (`ag`) — тоже.
- `rs1` — встроенный ресурс «Золото»: запас золота фракции и есть её казна.

### 3.4 Перечисления

Записываются строковыми идентификаторами. Неизвестное значение заменяется значением по умолчанию (первым в списке, если не указано иное) с предупреждением, где перечислены допустимые варианты.

| Поле | Значения (по умолчанию — **жирным**) |
| --- | --- |
| `Province.size` | `small` (1 слот), **`medium`** (2), `large` (3) |
| `Province.city` | `outpost`, **`village`**, `town`, `city` |
| `Faction.kind` | **`state`** — государство, `guild` — торговая гильдия, `wild` — «Без государства» (войска стражей и вторжений из археологических мест; одна на мир, враждебна всем) |
| `ArmyRow.type` (строка армии), `SpecialUnit.type` | **`light_inf`**, `medium_inf`, `heavy_inf`, `light_cav`, `medium_cav`, `heavy_cav`, `air_cav` — воздушная кавалерия, `flying`, `casters`, `ranged`, `beasts`, `monsters`, `machines`, `elementals` — элементали (у особого отряда по умолчанию — `monsters`) |
| `FleetRow.type` (строка флота) | `ship_line` — линкор, **`frigate`** — фрегат, `galleon` — торговый галеон, `sea_monster` — морское чудовище |
| `Relation.s` | `war` — война, `alliance` — союз, `neutral` — статус-кво, **`unknown`** — незнакомы |
| `Building.cat` | `military`, **`economic`**, `industrial`, `residential` — жилые и сельско-хозяйственные, `religious` — религиозные, `cult` — культовые |
| `Relic.rarity` | **`common`** — обычная, `rare` — редкая, `epic` — эпическая, `legendary` — легендарная, `epochal` — эпохальная |
| `Army.kind` | **`army`** — войско, `fleet` — флот |
| `Deal.kind` | **`trade`** — сделка, `tribute` — дань, `reparations` — репарации |
| `DealItem.from` | **`a`**, `b` — какая сторона отдаёт |
| `DealItem.mode` | **`once`** — разово, `turn` — каждый ход |
| `Deal.status` | **`active`**, `done`, `cancelled` |
| `LogEntry.kind` | `turn`, `economy`, `build`, `tech`, `war`, `battle`, `army`, `fleet`, `diplomacy`, `trade`, `province`, `guild`, `population`, **`note`**, `arch` — археология |
| `Flag.pattern` | **`solid`**, `h2`, `h3`, `v2`, `v3`, `cross`, `saltire`, `quarters`, `bend`, `chevron`, `border`, `canton`, `chief`, `pale` |
| `Settings.occupiedIncome` | **`owner`** — владельцу, `occupier` — оккупанту, `none` — никому |
| `Faction.stateKind` | **`living`** — государство живых, `undead` — нежити, `demonic` — демонов |
| `Modifier.kind` | **`any`**, `province`, `faction`, `army`, `hero`, `arch` — для археологических групп |
| `DealItem.kind` | **`res`**, `province`, `hero` |
| `Constant.type` | **`number`**, `resources`, `values` |
| `ChestItem.kind` | **`treasure`** — археологическая награда, `gold`, `res`, `relic` — артефакт, `essence`, `chest` — сундук |
| `Edge.kind` | **`border`** — граница, `coast` — берег, `frame` — рамка карты |
| `Edge.tl`, `Edge.tr` | `none` — вне карты, **`land`** — суша, `sea` — море |

### 3.5 Цвета, двоичные данные, строки

- Цвет — `"#rrggbb"` (строчные шестнадцатеричные цифры). Полупрозрачный цвет — `"#rrggbbaa"`. При чтении допускается и `"#rgb"`.
- Двоичные данные (изображение флага, портрет) — строка base64 (стандартный алфавит, дополнение `=`). При чтении пробелы и переводы строк внутри base64 пропускаются, допускается data URI `"data:image/png;base64,..."`.
- Текст — любые символы Юникода (кириллица, эмодзи). Переводы строк внутри текста — экранированные `\n`.

### 3.6 Пропуски и неизвестные поля

- Отсутствующее поле или `null` — значение по умолчанию (указано в таблицах ниже).
- Неизвестное поле отбрасывается с предупреждением «неизвестное поле отброшено» (опечатки в именах полей видны сразу).
- Значение неверного типа (строка вместо массива и т. п.) — поле пропускается с предупреждением.
- Элемент массива записей, не являющийся объектом, пропускается.

## 4. world.json

```json
{
  "format": "regnum-world",
  "meta": {
    "basemap": "wmm-expanded-v1",
    "createdAt": "2026-09-01T10:00:00Z",
    "mapObjects": true,
    "name": "Мир Ардена",
    "notes": "",
    "seq": {"army": 2, "building": 2, "character": 3, "council": 2, "culture": 3, "deal": 2, "edge": 2, "faction": 3,
            "government": 6, "log": 5, "modifier": 2, "node": 4, "position": 6, "province": 3, "race": 2,
            "religion": 2, "resource": 7, "route": 2, "row": 5, "shape": 156, "symbol": 5321, "tech": 2},
    "turn": 7,
    "updatedAt": "2026-10-01T11:22:33Z"
  },
  "settings": {
    "autosaveFolder": true,
    "autosaveSec": 60,
    "fillOpacity": 0.5,
    "labelArmies": true,
    "labelProvinces": true,
    "labelStates": true,
    "occupiedIncome": "owner",
    "rebellionRoll": false
  },
  "version": 1
}
```

| Поле | Тип | По умолчанию | Смысл и пределы |
| --- | --- | --- | --- |
| `format` | строка | — | всегда `"regnum-world"`; иное значение — отказ «это не мир Regnum» |
| `version` | число | 1 | старшая версия формата (раздел 12) |
| `meta.name` | строка | «Новый мир» | название мира |
| `meta.createdAt`, `meta.updatedAt` | строка ISO 8601 | `""` | время создания и последнего изменения (UTC) |
| `meta.turn` | целое | 1 | текущий ход, 1…1 000 000 |
| `meta.seq.<вид>` | целое ≥ 0 | 0 | последний выданный ID вида (раздел 3.3); не меньше наибольшего ID в данных |
| `meta.basemap` | строка | `wmm-expanded-v1` | идентификатор базовой карты (`id` в `assets/basemap/map.json`) |
| `meta.mapObjects` | логическое | `false` | мир хранит свои объекты карты (`data/map.json`); `false` — показываются объекты базовой карты (раздел 6.1). Объекты в файле при `false` — флаг ставится с предупреждением; `true` без файла — снимается |
| `meta.content` | целое | 0 | версия базовых записей справочников (`core/content.h`); мир меньшей версии дополняется при чтении один раз (раздел 11) |
| `meta.notes` | строка | `""` | заметки |
| `settings.fillOpacity` | число | 0.5 | непрозрачность заливки провинций, 0…1 |
| `settings.labelStates`, `labelProvinces`, `labelArmies` | логическое | `true` | подписи государств, провинций, войск на карте |
| `settings.showArmies` | логическое | `true` | войска и флот на карте («Скрыть войска» — `false`) |
| `settings.figureSize` | целое | 34 | размер значка войска и флота на экране, точки (18…72), постоянный при любом масштабе |
| `settings.occupiedIncome` | перечисление | `owner` | кому идёт доход оккупированной провинции |
| `settings.rebellionRoll` | логическое | `false` | бросок восстания в конце хода |
| `settings.autosaveFolder` | логическое | `true` | автосохранение в папку проекта |
| `settings.autosaveSec` | целое | 60 | период автосохранения, 10…3600 с |
| `settings.freeFleets` | логическое | `false` | «Свободное редактирование флотов»: новый флот ставится в любое место карты; иначе — из вкладки «Флот» государства у его верфи |
| `meta.rng` | целое ≥ 0 | 0 | счётчик случайных событий мира (археология): зерно броска — счётчик и ID участников |

## 5. data/catalogs.json — справочники

Семь простых списков: `resources`, `races`, `cultures`, `religions`, `governments`, `positions`, `essences` (эссенции элементов), и списки `resGroups` (группы ресурсов), `relics` (реликвии), `relicGroups` (группы реликвий), `specials` (особые отряды), `classes` (классы героев с деревьями талантов), `archSites` (археологические места), `chests` (сундуки сокровищ). Порядок элементов сохраняется (это порядок в интерфейсе).

    {"id": "rg9", "key": "provisions", "name": "Провизия", "parent": null},
    {"id": "rg10", "key": "provAgri", "name": "Сельскохозяйственная", "parent": "rg9"}

  "essences": [{"builtin": false, "color": "#ff6a2b", "icon": "essence", "id": "es1", "name": "Эссенция пламени"}],

  "specials": [
    {"desc": "", "essUpkeep": {}, "essence": {"es18": 1000}, "extra": {"rs145": 100}, "id": "su1", "keyPer": 1, "keyRes": "rs62",

}
```

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `id` | ссылка своего вида (`rs`, `rc`, `cu`, `rl`, `gv`, `po`, `es`) | новый ID | уникален в списке |
| `name` | строка | `""` | название |
| `color` | цвет | `#888888` | цвет на карте и в диаграммах |
| `icon` | строка | `""` | имя значка |
| `builtin` | логическое | `false` | встроенный элемент (не удаляется в интерфейсе) |
| `key` | строка | `""` | только ресурсы: встроенный ресурс — `corpses` (трупы), `demonEnergy` (демоническая энергия), `mechParts` (запчасти механизмов — ключевой ресурс военных механизмов); `rs1` — всегда золото. Прежний ключ `provisions` (ресурс «Провизия» до групп ресурсов) при чтении снимается: ресурс переносится в группу «Провизия» (неиспользуемый — удаляется), отрицательный запас становится недостачей провизии `provisionDebt` |
| `group` | `rg…` или `null` | `null` | только ресурсы: группа справочника; несуществующая — ресурс без группы |
| `modifiers`, `vacantModifiers` | `["m…"]` | `[]` | только должности: глобальные модификаторы, действующие на государство, пока должность занята (пустует) |

`rs1` («Золото», казна) существует всегда: если его нет, он добавляется при чтении.

Группа ресурсов (`resGroups`): `id` (`rg…`), `name`, `parent` (`rg…` или `null` — верхний уровень; несуществующая или цикл — группа становится верхнего уровня), `key` — базовая группа, на которую опираются правила или которую дополняет миграция: `ore`, `oreCommon`, `oreSpecial`, `beasts`, `mountsGround`, `mountsFlying`, `warBeasts`, `monsters`, `provisions`, `provAgri`, `provAnimal`, `provGather`, `materials`, `matRaw`, `matPrecious`, `matAlchemy`, `matIndustrial` (без повторов; неизвестный снимается). Группы правил — `provisions` (расход провизии и голод), `beasts`, `mountsGround`, `mountsFlying`, `monsters` (ключевой ресурс войск) — не удаляются. Ресурсы группы — ресурсы с её `group` и ресурсы всех её подгрупп.

Реликвия (`relics`): `id` (`re…`), `name` (уникально), `rarity` (перечисление; главенство: эпохальная > легендарная > эпическая > редкая > обычная), `desc`, `group` (`rlg…` или `null`), `entity` (ID карточки проекта: её портрет — значок реликвии), `image` (base64 PNG/JPEG — своё изображение; иные данные удаляются). Реликвия не имеет количества и лежит не больше чем в одном месте: инвентарь персонажа (`Character.inventory`), хранилище постройки провинции (`buildings[].relics`), реликвии государства (`Faction.relics`) или тайник провинции (`hiddenRelic`). При повторе остаётся первое место в порядке: реликвии государств, инвентари персонажей, постройки и тайники провинций (по возрастанию ID).

Группа реликвий (`relicGroups`): `id` (`rlg…`), `name`, `parent` (`rlg…` или `null`; без циклов), `key` — `archFinds` у группы «Археологические находки» (её реликвии героям напрямую не назначаются; из неё выбираются артефакты сундуков и раскопок).

Класс героя (`classes`): `id` (`hc…`), `name`, `desc`, `icon`, `color`, `tierPoints` (1…60, по умолчанию 5: талант яруса r доступен, когда в верхних ярусах вложено не меньше r × tierPoints очков), `talents` — таланты дерева: `id` (`tl…`, уникален во всём мире), `name`, `desc`, `icon`, `row` (ярус 0…49), `col` (столбец 0…3; в ячейке — один талант, повтор переносится в ближайшую свободную), `cost` (очков 1…5), `prereq` (`tl…` того же класса из яруса выше или `null`), `modifiers` (`["m…"]` — модификаторы героя, пока талант изучен).

Археологическое место (`archSites`): постоянный список из десяти мест с ключами `ruins`, `crypt`, `tunnels`, `valley`, `temple`, `citadel`, `portal`, `tomb`, `labyrinth`, `vault` (повтор или неизвестный ключ — запись удаляется, недостающие добавляются базовыми записями); `id` (`as…`), `name`, `icon`, `rewards` — четыре списка сундуков (`[["ch…"], …]`) — «Финальная награда исследования» для слотов «Обычное», «Редкое», «Эпическое», «Легендарное место».

Сундук сокровищ (`chests`): `id` (`ch…`), `key` (базовый сундук: `small`, `box`, `casket`, `woodChest`, `woodCoffer`, `reinfChest`, `reinfCoffer`, `steelChest`, `steelCoffer`, `mithrilChest`, `mithrilCoffer`, `cultist`, `necromancer`, `jarl`, `offering`, `emperor`; свой — пусто), `name`, `icon`, `desc`, `items` — поля: `kind`, `amount` (≥ 0; у сундука — 1), а по виду: ресурс — `res` (конкретный или `null`), `group` (`rg…` — случайный из группы), `exclude` (`["rs…"]`); эссенция — `essence` (`es…` или `null` — случайная); артефакт — `relicGroup`, `rarities` (`["rare", "epic"]` — допустимые редкости); сундук — `chests` (`["ch…"]`, случайный из списка; цикл вложенных сундуков разрывается).

Особый отряд (`specials`): `id` (`su…`), `name`, `type` (тип отряда), `race` (пусто — по виду государства и типу; у элементалей — `Элементали`), `keyRes` (ключевой ресурс, раздел 7.2 `army`), `keyPer` (на юнит: 1; у военных механизмов ≥ 1), `extra` (`{"rs…": на юнит}`, у элементалей — пусто), `essence` (`{"es…": на юнит}`), `upkeep` (золото за юнит в ход), `essUpkeep` (`{"es…": за юнит в ход}`, только у элементалей), `desc`. Строки армий с этим отрядом (`ArmyRow.special`) повторяют его поля.

## 6. data/geo.json — геометрия

Плоский граф провинций: узлы и дуги. Дуга — полилиния `a → pts… → b`. Стороны дуги помечены провинцией (`pl` — слева, `pr` — справа по ходу от `a` к `b`) и рельефом (`tl`, `tr`). Грань графа — часть провинции; провинция может состоять из нескольких граней (острова). Береговые дуги (`coast`, рельеф по сторонам разный) и рамка карты (`frame`) создаются из береговой линии базовой карты. При правке границ берег и рамка закреплены; в режиме «Правка карты» берег правится: точки берега двигаются, добавляются и удаляются, а «Добавить сушу» и «Убрать сушу» меняют рельеф граней внутри контура — дуга становится берегом там, где рельеф по её сторонам разный. Море в редакторе рисуется по этим дугам.

```json
{
  "edges": [
    {"a":1,"b":2,"id":1,"kind":"frame","pl":null,"pr":null,"pts":[],"tl":"sea","tr":"none"},
    {"a":5,"b":6,"id":5,"kind":"coast","pl":"p3","pr":"p8","pts":[5573.5,20.18,5622.5,28.24],"tl":"land","tr":"sea"}
  ],
  "nodes": [
    [1,0,0],
    [2,8000,0]
  ]
}
```

| Поле | Формат | Смысл |
| --- | --- | --- |
| `nodes[i]` | `[id, x, y]` | узел: ID (число без префикса) и координаты |
| `edges[i].id` | число | ID дуги |
| `edges[i].a`, `b` | число | ID начального и конечного узла |
| `edges[i].pts` | `[x1, y1, x2, y2, …]` | промежуточные точки (без `a` и `b`); при чтении допускаются и пары `[[x1, y1], …]` |
| `edges[i].kind` | перечисление | `border`, `coast`, `frame` |
| `edges[i].pl`, `pr` | ссылка `p` или `null` | провинции слева и справа; `null` — не назначено |
| `edges[i].tl`, `tr` | перечисление | рельеф слева и справа: `land`, `sea`, `none` (вне карты) |

Правка геометрии вручную возможна, но корректность графа (без пересечений, замкнутые грани, согласованные метки сторон) проверяет только `regnum-cli validate`; надёжнее править границы в редакторе.

### 6.1 data/map.json — объекты карты мира

Горы, замки, башни, воды, островки, стены и реки, которые редактор рисует кодом поверх суши и моря. Пока карту мира не правили (`meta.mapObjects` = `false`), файл содержит пустые списки, а мир показывает объекты базовой карты (`assets/basemap/map.json`, раздел 14). Первая правка карты в редакторе переносит их в мир с теми же ID (знаки — 1…n в порядке отрисовки, фигуры — вода, островки, стены, реки) и ставит флаг; дальше у мира своя карта. Запись на строку, как у `geo.json`.

```json
{
  "shapes": [
    {"holes":[[2040,2040,2040,2060,2060,2060,2060,2040]],"id":1,"kind":"water","pts":[2000,2000,2100,2000,2100,2100,2000,2100]},
    {"id":2,"kind":"islet","pts":[3000,3000,3010,3000,3005,3008]},
    {"dash":3,"id":3,"kind":"wall","pts":[100,4000,200,4010.5,300,4000],"w":2.5},
    {"id":5,"kind":"river","pts":[500,500,600,650],"w":6}
  ],
  "symbols": [
    [1,"mountain",1200.25,800.5,1,1,0],
    [2,"peak",1300,820,2.25,0,1.5]
  ]
}
```

| Поле | Формат | Смысл и пределы |
| --- | --- | --- |
| `symbols[i]` | `[id, вид, x, y, масштаб, рисунок, z]` | знак: вид `mountain` (гора), `peak` (крупная гора), `castle`, `tower`; (x, y) — середина основания значка; масштаб 0,2…8 (1 — как на исходной карте); рисунок горы 0 или 1 (у прочих 0); z — порядок отрисовки (больше — выше; при равных — по ID). Без z — 0 |
| `shapes[i].id` | число | ID фигуры |
| `shapes[i].kind` | перечисление | `water` — озеро или река контуром, `islet` — островок (рисунок, в геометрию провинций не входит), `wall` — стена, `river` — река линией |
| `shapes[i].pts` | `[x1, y1, …]` | контур (`water`, `islet`, не менее 3 точек) или линия (`wall`, `river`, не менее 2 точек) |
| `shapes[i].holes` | `[[x1, y1, …], …]` | острова внутри воды (только `water`), по 3 точки и больше |
| `shapes[i].w` | число | ширина линии `wall` и `river`, 0,25…100 (по умолчанию 2 и 4) |
| `shapes[i].dash` | число | длина штриха пунктирной стены (0 или нет — сплошная) |

Воды заливаются правилом NonZero с ориентацией колец по вложенности (редактор приводит её сам), поэтому пересекающиеся озёра сливаются, а острова остаются сушей. Точки вне карты переносятся на край, неверные виды и короткие контуры отбрасываются с предупреждением.

### 7.4 data/relations.json

Отношения симметричны; ключ — пара фракций `"f<меньший ID>|f<больший ID>"`, по одной паре на строку. Пары, которых нет в файле, — «незнакомы», значение 0.

```json
{
  "relations": {
    "f1|f2": {"s":"alliance","v":50.5},
    "f1|f3": {"s":"war","v":-25}
  }
}
```

| Поле | Тип | По умолчанию | Правило |
| --- | --- | --- | --- |
| `v` | число | 0 | значение отношений, −100…100 |
| `s` | перечисление | `unknown` | состояние: `war`, `alliance`, `neutral`, `unknown` |

Пара с несуществующей фракцией или фракции с самой собой удаляется. Порядок в ключе при чтении не важен (`"f3|f1"` = `"f1|f3"`); повтор пары — берётся последнее значение.

```json
{
  "modifiers": [
    {"color": "#33aa55", "desc": "", "fx": {"diplomacyPerTurn": -5, "tradePct": 10}, "icon": "trade", "id": "m1",
     "name": "Торговый бум", "targets": ["f3"]}

```json
{
  "constants": [
    {"builtin": true, "desc": "", "key": "colonizationCost", "name": "Стоимость колонизации", "num": 500, "type": "number"},

    {"builtin": false, "desc": "", "key": "user1", "name": "Свои расы", "type": "values", "values": ["Гоблины", "Тролли"]}
  ]
}
```

| Поле | Тип | По умолчанию | Правило |
| --- | --- | --- | --- |
| `key` | строка | — | устойчивый ключ: встроенные — ниже, свои — `user1`, `user2`…; без ключа или повтор — назначается новый |
| `name`, `desc` | строка | `""` | название и описание |
| `type` | перечисление | `number` | `number` — число (`num`), `resources` — список ресурсов с количествами (`res`), `values` — список значений (`values`) |
| `builtin` | логическое | `false` | встроенная константа (не удаляется, тип не меняется) |

Встроенные: `colonizationCost` — стоимость колонизации, золото (0); `shipLineCost`, `frigateCost`, `galleonCost`, `seaMonsterCost` — ресурсы (и эссенции `ess`) на один линкор, фрегат, торговый галеон, морское чудовище; `unitRaces` — расы для отрядов (`Живой`, `Демонический`, `Нежить`, `Механический`, `Элементали`, `Наемники`); `corpsesPerUnit` — трупов на 1 воина-нежить (1); `energyPerUnit` — демонической энергии на 1 воина-демона (100); `frigateCapacity`, `shipLineCapacity` — вместимость фрегата и линкора (1000, 5000 воинов); `mercPerGuild` — наёмников за гильдию наёмников (2500); `mercHire` — найм наёмника, золото за юнит у новой строки (0,01); `archGroupPeople`, `archGroupGold` — цена археологической группы (100 жителей или трупов, 5 золота).

У константы-списка ресурсов ещё: `ess` (`{"es…": число}` — эссенции), `minRes`, `minEss` — базовая (наименьшая) стоимость: значение не может быть меньше её, а позиция — убрана (при чтении меньшее поднимается). Базовая стоимость кораблей: галеон — 100 древесины, 10 золота, 100 ткани; фрегат — 250 древесины, 25 золота, 250 ткани, 50 железа; линкор — 1000 древесины, 100 золота, 1000 ткани, 250 стали; морское чудовище — 750 эссенции воды.

## 8. Резервные копии

Перед перезаписью файла его прежняя версия кладётся в `.regnum-backup/` с той же вложенностью: `.regnum-backup/data/provinces.000012.json`, `.regnum-backup/world.000003.json`. Номер растёт; хранятся последние 5 версий каждого файла. Версии, записанные автосохранением в папку мира, при перезаписи кладутся в отдельную очередь `.regnum-backup/auto/` (тоже 5 версий), поэтому частые автосохранения не вытесняют копию версии, сохранённой вручную. В папке лежит `.gitignore` со строкой `*` — копии не попадают в Git. Восстановление — заменить файл мира копией и перечитать мир.

## 9. Внешние изменения

При чтении и сохранении редактор запоминает для каждого файла мира размер, время изменения и CRC-32 содержимого. Файл считается изменённым другой программой, если изменились размер или время и при этом изменилось содержимое (перезапись тем же текстом изменением не считается). Изменённые, удалённые и появившиеся файлы показываются пользователю с предложением перечитать мир. Сохранение поверх файла, изменённого извне, требует явного подтверждения: Ctrl+S предлагает «Перечитать», «Сохранить с заменой» или «Отмена»; автосохранение в папку такие файлы не перезаписывает. Архив `.regnum` отслеживается целиком так же (размер, время и CRC-32 файла архива).

## 10. История ходов, архив, данные пользователя

### 10.1 Снимки ходов

`history/turn-NNNN-SSSSSS.json.gz` (NNNN — номер хода, не меньше четырёх цифр; SSSSSS — номер снимка, уникальный в истории мира) — весь мир на момент хода в одном документе, сжатом gzip. Снимки не заменяют друг друга; редактор создаёт три вида снимков:

- `start` — начало хода: мир сразу после расчёта прошлого хода (или при первом открытии мира на этом ходу). К нему ведёт «Начать ход заново».
- `end` — конец хода: мир перед расчётом. Его открывают «Посмотреть» и «Вернуться к ходу» для прошлых ходов.
- `branch` — состояние перед возвратом к другому ходу (брошенная ветвь, к ней можно вернуться).

Новые снимки хранятся в памяти редактора и записываются в `history/` только при сохранении мира (вручную или автосохранением в папку); «Не сохранять» отбрасывает их вместе с миром. Время `at` — время создания снимка, оно сохраняется при сохранении, «Сохранить как» и преобразовании. При сохранении мира в чужую папку или поверх чужого архива история места заменяется историей этого мира. Документ снимка:

```json
{
  "files": {
    "data/catalogs.json": { …содержимое файла… },
    "data/geo.json": { … },
    …
    "world.json": { … }
  },
  "format": "regnum-snapshot",
  "version": 1
}
```

Каждый член `files` — то же значение, что в одноимённом файле проекта, поэтому снимок читается тем же кодом с той же нормализацией.

`history/index.json` — список снимков по возрастанию хода, затем номера, и `head` — номер снимка, от которого идёт сохранённый мир (по нему редактор находит начало и конец ходов текущей ветви):

```json
{
  "head": 15,
  "snapshots": [
    {"at": "2026-10-01T20:00:00Z", "file": "turn-0007-000014.json.gz", "kind": "end", "label": "Ход 7", "name": "Мир Ардена", "parent": 13, "seq": 14, "size": 48211, "turn": 7},
    {"at": "2026-10-01T20:00:01Z", "file": "turn-0008-000015.json.gz", "kind": "start", "label": "Начало хода 8", "name": "Мир Ардена", "parent": 14, "seq": 15, "size": 48390, "turn": 8}
  ]
}
```

`parent` — предыдущий снимок той же ветви: у начала хода — конец прошлого хода, у конца хода и состояния перед возвратом — снимок, от которого шёл мир. Если `index.json` потерян или в нём нет файла, снимки находятся по именам (без подписи и вида). Снимки прежнего формата `turn-NNNN.json.gz` (без номера, один на ход) читаются: «Снимок того же хода заменяет прежний» действует только для них.

### 10.2 Архив .regnum

Обычный zip с той же раскладкой: `world.json` (первым), `data/*.json`, `history/`. Мир может лежать и в единственной вложенной папке архива (`Мир/world.json`) — так получается при упаковке папки целиком. Запись архива атомарная; при сохранении архива его история ходов сохраняется (и дополняется несохранёнными снимками), а при записи другого мира поверх архива его прежняя история удаляется. Преобразование папки и архива — `regnum-cli convert`.

### 10.3 Данные пользователя

Папка данных пользователя: Windows `%APPDATA%/Regnum`, Linux `$XDG_CONFIG_HOME/regnum` или `~/.config/regnum`, macOS `~/Library/Application Support/Regnum`.

- `recent.json` — недавние проекты: `{"recent": [{"at": …, "name": …, "path": …}]}`, новые первыми, не больше 12.
- `autosave/autosave-<слот>.json.gz` — автосохранение мира (документ снимка, раздел 10.1) для восстановления после сбоя; `autosave/autosave-<слот>.json` — сведения: `{"at", "name", "project", "turn"}`. Слот — 16 шестнадцатеричных цифр хеша полного пути проекта или `new` для несохранённого мира. Одному проекту соответствует один слот. Восстановление предлагается (на экране запуска и при открытии мира), если автосохранение новее последнего сохранения мира — `meta.updatedAt` в `world.json` (если его нет — время файла). Сохранение мира удаляет автосохранение его слота.

## 11. Нормализация при чтении

После чтения мир приводится к инвариантам схемы. Каждое исправление — предупреждение `файл: место: что исправлено`; таблицы с исправлениями переписываются при следующем сохранении. Нормализация идемпотентна: повторный проход по исправленному миру ничего не меняет.

1. **Ссылки.** Ссылка на несуществующую запись обнуляется (одиночная) или удаляется (в списке). Исключение — хроника (раздел 7.11).
2. **Пределы.** Числа вне пределов прижимаются к границе, нечисловые заменяются значением по умолчанию (пределы — в таблицах разделов 4–7).
3. **Повторы.** Повторы в списках ссылок удаляются; повторы строк гарнизона, отрядов, рас, влияния складываются; повторная постройка провинции удаляется.
4. **ID.** Запись без ID или с повторным ID получает новый ID. Повтор ID строки армии или места совета в другой фракции получает новый ID; ссылки этой фракции (гарнизоны её провинций, её отряды в войсках) переводятся на новый ID.
5. **Счётчики.** `meta.seq.<вид>` не меньше наибольшего ID вида (иначе поднимается).
6. **Справочники.** `rs1` «Золото» всегда есть и отмечен встроенным. Группы ресурсов — без циклов, с известными ключами; группа бывает только у ресурса. Цены особых отрядов — как у строк армии (раздел 7.2).
7. **Провинции.** Владелец — только государство; оккупант — государство, отличное от владельца; гарнизон — строки армии владельца, герои гарнизона — доступные герои владельца (каждый — в одном месте); штабы — до 5 гильдий; сумма влияния гильдий ≤ 100 % (пропорциональное уменьшение); уплаченное за строительство — только у строящейся постройки, плательщик — государство; состояние преобразования — только у постройки преобразования.
8. **Фракции.** У государства нет `homeState` и `stateGuild`; `homeState` гильдии — государство; флаг-изображение — только PNG. Ключевой ресурс строки армии — подходящий её типу; строка особого отряда повторяет его запись; изучение — только общих технологий.
9. **Деревья.** Требования построек и условия технологий без циклов; условия технологии — в дереве той же фракции (у технологии государства — ещё и общие); общая постройка зависит только от общих построек и технологий, уникальная — ещё и от своих; технология несуществующей фракции удаляется (без фракции — общая); изученная технология с неизученным условием теряет изученность (общая — у каждой фракции отдельно); уникальная постройка гильдии становится общей; данные выключенных возможностей постройки (рецепт, эссенции уровней, особые отряды) снимаются.
10. **Войска.** Отряды — строки своей фракции (армии для войска, флота для флота); герой — не больше чем в одном войске или гарнизоне; войско без групп удаляется; положение — в пределах карты.
11. **Маршруты и сделки.** Маршрут без двух точек удаляется; сделка без двух различных сторон удаляется.
12. **Геометрия.** Узел с нечисловыми координатами удаляется, точки вне карты переносятся на край; дуга с несуществующим узлом или вырожденная петля удаляется; ссылки дуг на провинции проверяются. Топология графа (пересечения, замкнутость граней) нормализацией не исправляется — её проверяет `regnum-cli validate`.
13. **Миры прежней версии.** Мир с `meta.content` меньше текущей версии один раз дополняется базовыми записями (`core/content.cpp`, предупреждение «мир дополнен: …»): должности «Канцлер», «Казначей», «Маршал», «Адмирал», «Тайный советник», «Придворный маг» переименовываются в «Десница», «Лорд-Мастер над экономикой», «… над войной», «… над флотом», «… над разведкой», «Хранитель знаний» (вместе с местами совета), добавляются «Патриарх», «Верховный магистр», «Архимаг», «Верховный друид»; добавляются 18 эссенций элементов, группы ресурсов «Руда», «Звери», «Провизия», «Материалы» с подгруппами и ресурсами (существующий ресурс с тем же названием не дублируется, а получает группу), 61 религия, трупы, демоническая энергия, запчасти механизмов, особый отряд «Драконы Бездны» и общая постройка «Цитадель Бездны». Прежний ресурс «Провизия» переносится в группу «Провизия» (если нигде не используется — удаляется). Записи, удалённые пользователем после этого, не возвращаются. Героям государств без модификатора природы назначается природа по виду государства («Живой», «Нежить», «Демон») — один раз: только пока в мире нет записи этого встроенного модификатора; после этого природу меняют по правилам модификаторов.

14. **Доработки 2026-10-10 (версия базовых записей 2).** Мир прежней версии один раз дополняется: группа «Валюты» (золото, трупы, демоническая энергия и новые «Археологические сокровища», «Древние свитки Шантири»), подгруппа «Звери / Морские чудовища» с пятью ресурсами, уголь, проклятые, освящённые и осквернённые металлы, «Скакуны алой зари», 9 религий, группа реликвий «Археологические находки», 16 сундуков сокровищ, 10 археологических мест, 20 классов героев, общие постройки (порт, верфь, гильдия наёмников, шантирийские постройки, 9 построек доступа к особым отрядам, 18 храмов и 18 соборов эссенций), 9 особых отрядов, ветка общих технологий «Археология» (10), базовая стоимость кораблей, «Гильдия Археологов» в дереве каждого государства, генерация «Некроманта» (+10 эссенции смерти). Пустые археологические слоты провинций заполняются.

Чтение отказывает (сообщение по-русски, мир не открывается) только если: нет `world.json`; файл не является корректным JSON (указываются файл, строка и столбец); `format` не `regnum-world`; версия формата новее поддерживаемой; архив повреждён.

## 12. Версии формата

`version` в `world.json` и в снимках — старшая версия формата, сейчас 1. Дробная часть (`1.4`) — младшая версия: файлы того же старшего номера читаются (неизвестные поля отбрасываются с предупреждением). Мир с большей старшей версией не открывается: «Мир сохранён более новой версией Regnum… Обновите редактор». Несовместимые изменения формата увеличивают старшую версию; редактор читает все прежние версии и сохраняет в текущей.

## 13. Командная строка

`regnum-cli` (собирается `tools/Regnum/build.sh regnum-cli`, лежит в `tools/Regnum/bin/<ОС>/`). Путь мира — папка, её `world.json` или архив `.regnum`.

| Команда | Действие | Код возврата |
| --- | --- | --- |
| `validate <мир> [--json] [--strict]` | читает мир, выводит исправления нормализации (раздел 11), ошибки геометрии, файлы, которые будут переписаны при сохранении, и файлы не в каноническом виде | 0 — ошибок нет; 1 — мир не читается или есть ошибки геометрии (с `--strict` — и при любых исправлениях) |
| `inspect <мир> [--json]` | сводка: ход, число сущностей, казна фракций, провинции по владельцам, снимки ходов | 0; 1 — мир не читается |
| `convert <откуда> <куда> [--force]` | папка → архив или архив → папка (по расширению назначения) с историей ходов; мир читается с нормализацией | 0; 1 — ошибка |
| `new <папка или файл.regnum> [--name=…] [--basemap=<папка>] [--no-geometry] [--force]` | новый мир со справочниками по умолчанию и геометрией из береговой линии базовой карты (по умолчанию `tools/Regnum/assets/basemap`) | 0; 1 — ошибка |
| `build-map <исходник.png> [папка] [--render=<png> [--crop=x,y,ш,в] [--diff=<png>]] [--debug=<папка>] [--id=…]` | разбирает изображение карты в объекты (раздел 14) и записывает `<папка>/map.json`; `--render` рисует результат кодом и печатает расхождение с исходником | 0; 1 — ошибка |

`validate --json` выводит объект `{"ok", "path", "bundle", "name", "turn", "errors": [{"code", "msg", "at": [x, y]}], "warnings": [{"file", "where", "msg"}], "rewrite": [файлы с исправлениями], "reformat": [файлы не в каноническом виде]}`; при ошибке чтения — `{"ok": false, "errors": [{"code": "load", "msg"}]}`. `inspect --json` — объект со счётчиками (`counts`), фракциями (`factions`: `id`, `kind`, `name`, `treasury`, `provinces` или `hqs`, `armies`), `provincesByOwner` и `history`.

## 14. Базовая карта: assets/basemap/map.json

Базовая карта не является изображением: редактор рисует её кодом из объектов `tools/Regnum/assets/basemap/map.json` (рядом с программой — `assets/basemap/map.json`). Это образец для миров: береговая линия становится геометрией нового мира (`data/geo.json`), а знаки и фигуры — объектами мира при первой правке карты (раздел 6.1). Файл собирается командой `regnum-cli build-map "tools/Regnum/assets/source/Expanded Map.png" tools/Regnum/assets/basemap` и вручную не правится: повторный разбор того же исходника даёт тот же файл байт в байт. Мир ссылается на карту через `meta.basemap` = `id`.

Координаты — пиксели исходника (0…`width`, 0…`height`, ось y вниз), числа с двумя знаками после запятой. Кольца и ломаные записаны плоскими массивами `[x0, y0, x1, y1, …]`.

| Поле | Значение |
| --- | --- |
| `format`, `version` | `"regnum-map"`, 1 |
| `id` | идентификатор карты (`wmm-expanded-v1`) |
| `source`, `sourceSha256` | имя исходного изображения и SHA-256 его файла |
| `width`, `height` | размер карты (8000 × 4500) |
| `style` | цвета `sea`, `land`, `water` (`#rrggbb`); `coastSoft` — ширина светлой каймы моря у берега (0–16), `coastGlow` — её сила (0–1) |
| `land` | кольца суши — береговая линия мира, по которой строится геометрия провинций |
| `islets` | мелкие островки (рисуются, в геометрию провинций не входят) |
| `water` | реки и озёра: кольца заливаются по правилу чётности, поэтому острова в озёрах — вложенные кольца |
| `rivers` | реки линиями переменной ширины `{"p": [...], "w": [ширины по точкам]}`; у текущей карты пусто — реки входят в `water` |
| `lines` | стены: `{"p": [...], "w": ширина, "dash": штрих}` (без `dash` — сплошная), рисуются чёрным с круглыми концами |
| `symbolKinds` | имена видов знаков: `mountain`, `peak` (крупная гора), `castle`, `tower` |
| `symbols` | знаки пятёрками `[вид, x, y, масштаб, вариант, …]` в порядке отрисовки (поздние перекрывают ранние); вид — номер в `symbolKinds`, (x, y) — середина нижнего края знака, вариант — рисунок горы (0 или 1) |

Значки знаков заданы в коде (`src/map/art_render.cpp`): замок и башня — наборы прямоугольников, при масштабе 1 совпадающие со штампами исходника пиксель в пиксель, гора — геометрический рисунок (тело, полосы склонов, шапка из трёх зубцов, тень), параметры которого подобраны по штампам исходника (`build-map --fit-icons`).
