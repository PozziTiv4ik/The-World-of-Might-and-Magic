# Проверка Atlas без Computer Use

---
type: tool_documentation
status: active
canon_level: support
updated_real_date: 2026-09-20
---

Atlas 5.2 умеет выполнять действия редактора без окна. Сценарий управляет настоящим App: используются общие обработчики команд, клавиш, указателя, меню, формы свойств и Direct2D-отрисовка. Такой прогон позволяет агенту править карту, видеть результат и повторять ошибки без доступа к рабочему столу.

## Запуск

Из корня проекта, в PowerShell 7:

```powershell
./tools/Atlas/test-editor.ps1 -Build
```

Без -Build используются готовые exe; скрипт сверяет их контрольные суммы и исходники с build-info.json. Устаревшая сборка отклоняется. Для отдельного сценария:

```powershell
./tools/Atlas/test-editor.ps1 -Scenario ./tools/Atlas/tests/scenarios/04-raster-cancellation.json
```

- -Scenario принимает один или несколько путей к JSON, по умолчанию запускаются все файлы scenarios.
- -CliPath выбирает сборку; при совместном -Build она собирается в эту папку.
- -MapDirectory задаёт исходную карту для сценариев с requires_map. По умолчанию используется 12_Карты/Карта_мира_Объекты.
- -OutputDirectory меняет каталог результатов; по умолчанию это .wmma/atlas-editor-tests.
- -TimeoutSeconds ограничивает отдельный процесс, по умолчанию 300 секунд. По тайм-ауту завершается только созданный тестовый CLI.

Прямой вызов без оболочки:

```powershell
./tools/Atlas/bin/Atlas.Cli.exe editor-test --scenario ./tools/Atlas/tests/scenarios/01-vector-editing.json --out ./.wmma/editor-check --project .
./tools/Atlas/bin/Atlas.Cli.exe editor-test --scenario ./tools/Atlas/tests/scenarios/10-campaign-copy.json --map ./12_Карты/Карта_мира_Объекты --out ./.wmma/editor-check --project .
```

Каждый запуск получает новую папку. Без --map создаётся тестовая карта, с --map копируется весь проект карты, кроме .atlas. Контрольные суммы исходника сверяются после прогона. Выбор файлов и папок ограничен каталогом теста; внешние ссылки и запуск приложений запрещены. Буфер обмена находится в памяти теста. Если нужна карта, но её нет, оболочка явно помечает сценарий как skipped, а прямой CLI отклоняет запуск.

## Сценарии

12 готовых файлов проверяют векторы и свойства, хронологию с клавиатуры, исторические даты и редакции, отмену растровой кисти, жесты и панели, слои и буфер обмена, отмену диалогов и ошибочные значения, общие политические границы, случайные операции, полную копию кампании, жизненный цикл файлов и дублирование геометрии.

Минимальный пример:

```json
{
  "schema_version": 1,
  "name": "label-roundtrip",
  "viewport": {"width": 1280, "height": 800, "dpi": 1},
  "create": {"name": "Тест", "width": 1600, "height": 1000},
  "steps": [
    {"action": "camera", "zoom": 1, "offset": [0, 0]},
    {"action": "key", "key": "T"},
    {"action": "answer", "answer": {
      "kind": "form", "title": "Подпись", "values": {"Текст": "Порт"}
    }},
    {"action": "click", "space": "world", "at": [420, 300]},
    {"action": "remember", "name": "port", "pointer": "/selection/0"},
    {"action": "key", "key": "Ctrl+S"},
    {"action": "restart"},
    {"action": "assert", "target": "document",
     "pointer": "/features/${port}/name", "equals": "Порт"},
    {"action": "capture", "capture": "saved-port"}
  ]
}
```

viewport задаётся в логических пикселях, dpi — множитель: 2 даёт PNG вдвое шире и выше. Минимум 800×500; снимок ограничен 33 млн пикселей. requires_map: true требует исходную карту. capture_all: true сохраняет снимок каждого шага. images создаёт небольшие одноцветные PNG для проверки кисти и импорта; пример — 04-raster-cancellation.json.

## Действия и проверки

Основные шаги:

- command: имя команды, например save, undo, redo, duplicate, layers, history, new_event, compare. Необязательный data содержит ID или параметр. Полный каталог — commands в src/editor_scenario.cpp.
- tool: имя инструмента — select, node, country, route, river, brush, symbol, label, eraser, pan, zone, trace, measure, rectangle, lasso, fill, picker, land, border.
- key: клавиша или сочетание, например Ctrl+H, Ctrl+Shift+S, Enter, Escape, PageDown, Tab. modifiers для действий указателя принимает ctrl, shift, alt, space.
- click, double_click, pointer_down, pointer_move, pointer_up: координаты at либо control с command, необязательными data и index. Выбор control ищет реальную отрисованную кнопку и нажимает её центр; неоднозначное или невидимое совпадение — ошибка.
- drag: from, to, необязательные segments, button: middle и preview: true для снимка до отпускания. space: world использует координаты карты, screen — логические координаты интерфейса, pixel — физические пиксели PNG. По умолчанию screen.
- wheel: at и delta, обычно 120 или -120. search задаёт text. resize меняет width, height, dpi. camera задаёт zoom и offset.
- wait: milliseconds двигает виртуальное время; autosave: true вызывает настоящий обработчик автосохранения. Физического ожидания нет.
- capture сохраняет снимок и данные; поле capture можно добавить к любому шагу.
- restart заново открывает сохранённую карту, validate_history проверяет все снимки, assert_ui проверяет размещение интерактивных элементов внутри экрана.

assert читает JSON Pointer из состояния редактора. target: document читает рабочий документ, saved — map.json на диске, file_hash — SHA-256 файла внутри прогона, geometry — координаты контуров feature. Операторы: equals, equals_ref, not_equals_ref, exists, count, gt, contains. epsilon задаёт допустимую погрешность чисел и массивов. Без оператора проверка отклоняется. assert с file проверяет наличие файла, contains — его текст, image_size — размеры PNG.

remember сохраняет значение по pointer в именованный псевдоним. Строка ${имя} подставляет ID или значение в последующих шагах; equals_ref сравнивает полное исходное значение, включая объект или массив. Это позволяет проверять отмену, хеши и геометрию без жёстко заданных случайных ID.

answer ставит в очередь ответ на следующий диалог. kind: form использует настоящие названия полей в values, все значения — строки; неизвестное поле или недопустимый вариант отклоняются. kind: menu выбирает единственный пункт по подстроке label. Для confirm используются yes/no/ok/cancel, для color — цвет в value, для folder/open_file/save_file — путь внутри прогона. cancel: true отменяет диалог. Неожиданный запрос или неиспользованный ответ проваливает сценарий. Системные окна не создаются.

clipboard с text задаёт содержимое внутреннего буфера. expect_error с подстрокой сообщения проверяет ожидаемый отказ операции; после этого модель должна оставаться корректной. При нормальных действиях исключение останавливает сценарий.

explore с seed и steps воспроизводит случайную последовательность создания, поворота, удаления и дублирования объектов. После каждой правки проверяется модель и точное восстановление документа через Undo/Redo. Готовый сценарий использует три seed по 120 операций. Для воспроизведения нужен тот же исходный документ, версия программы, seed и предшествующие шаги. Случайные ID объектов и время записи могут различаться; выбранные операции, координаты и цели фиксируются отдельно в trace.json.

## Результат и разбор ошибки

В папке suite-* находятся summary.json, index.html и журналы процессов. В каталоге сценария:

- scenario.json — точный входной сценарий;
- report.html и report.json — результат, шаги, ответы диалогов, число проверок;
- trace.json — журнал завершённых шагов;
- PNG и соседний JSON — отрисованный интерфейс, полный документ, выделение, камера, состояние жеста, история отмены и каталог видимых кнопок с координатами;
- failure-state.json и, для случайной правки, failure-before.json — данные для диагностики.

Для исправления прочитай failed_step и error, сопоставь состояние до/после, просмотри PNG, добавь короткий воспроизводящий сценарий, исправь общий обработчик и повтори проверку. Не подменяй исправление изменением ожидаемого результата при реальной потере данных. Успешный прогон возвращает код 0, провал — ненулевой. CI сохраняет отчёты и тестовые карты, в том числе после ошибки.

Проверки охватывают логику редактора, формы и общий рендер. Нативные системные диалоги Windows, физический фокус, презентация GPU, принтер и работа с несколькими мониторами этим режимом не проверяются. Набор дополняет self-test, проверку кампании и validate --history.
